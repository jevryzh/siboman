## 改动

1. **恢复 Seller portal 静默批量上架**（前端 BatchUpload.js `canUsePortal = false → true`）：
   - 一次把全店商品提交到草稿（create-bundle → update-bundle-items → upload-bundle），后台静默执行、绕官方 import 限流、不弹窗（复用已有 seller.ozon.ru tab，不新建 tab）。
   - **补齐 upload 任务轮询**（插件新增 `pollPortalUploadTask`，调 `/async-upload/v1/task/get-list`，15s×10 次）：确认真实上架结果（done/processing/failed），解决之前"ERP 显示提交但 Ozon 后台无商品"的隐患。
   - **三步重试**（插件新增 `portalWithRetry`，指数退避 1s/2s，对齐 MY ERP withRetry）：缓解 seller 后台偶发超时/抖动。
   - portal 通道失败（无 seller tab / cookie / 接口错误）→ 自动回退官方 import-by-sku 逐单提交（保留原路径，payload 不变）；portal 已真实提交但 task failed 时不重复提交。
2. **防超时**：
   - 服务端 `callOzonSellerAPI` 统一加 60s 超时（`AbortSignal.timeout`，可传参），超时报 504，不再无限挂起（前端先 60s 超时的根因之一）。
   - 前端官方 import 单次 axios timeout 60s → 120s。
   - 前端修复 `portalImport.request` 15s 默认超时 bug → 150s（之前 portal 三步 30-60s 必超时）。
3. **版本号** 2.2.9.77 → 2.2.9.78，StoreManagement 变更日志新增 v2.2.9.78 条目。
4. **测试守卫同步**：test_batch_listing_guard.cjs 与 erp-p1-acceptance-matrix.json 的 `canUsePortal = true` 及验收描述更新。
