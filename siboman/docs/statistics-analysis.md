# 统计分析

入口：`/#/statistics-analysis`。只在 `test.renwz.cn` 验收、部署，不操作生产。

## 统计口径

- 结算月份：先在已同步的全部正式应计流水中，取完整发运单号的最新应计日期，再选择月份。主订单号下的收单手续费收取或退回不决定月份。查询10月时也须检查11月及之后已产生的正式流水。
- 订单金额：只累计所选月份的根级正数和根级负数绝对值。正数包括手续费退回，不能理解为全是商品销售款。取消订单保留实际退费和物流扣费。
- 正常销售、WHD按实际订单渠道及 `Whd` 配送模式识别。取消原因保留官方文本，已知俄文原因翻译为中文，未知原因保留原文或标记原因代码，不编造。
- 主订单共用费用仅在唯一子单或SKU唯一匹配时分配。同一SKU分属多个子单时留待分摊，不按件数或售价猜分。缺失金额不替换为0。
- 订单毛利（CNY）=（正向入账RUB − 订单扣费RUB）× 汇率 − 采购费用 − 贴单费用。不含店铺广告。
- 月度毛利（CNY）=（所选结算订单正向入账 − 订单扣费 ＋ 当月其他店铺净收支）× 汇率 − 采购费 − 贴单费 − 当月广告费CNY。店铺广告不再计入订单扣费；订单上已经包含的费用不重复加到店铺广告中。
- 店铺广告取无订单号的广告应计流水净费用，广告类型ID为3、4、19、23、33、41、49、54、87、130。广告退回冲减广告费。手工覆盖可选CNY或RUB，0是有效覆盖；恢复API模式须将覆盖值设为null。
- 汇率为1 RUB对应CNY。默认使用ERP最新汇率，也可固定本月汇率。没有隐含的人民币/卢布加减。
- 采购费按单维护，含采购运费；贴单费默认1.50元，包括取消单，可手工修改。未录入采购费、存在共用收支待分摊或数据未同步完整时，毛利保留待核算，已录入采购费合计不是完整成本。

## 同步与隔离

- 应计：`/v1/finance/accrual/by-day`，逐日循环`last_id`，空日期也保存覆盖记录。异常游标、响应币种或日期不一致时停止，不以空数据覆盖旧日期。
- 订单：`/v4/posting/fbs/list`、`/v3/posting/fbo/list`；按完整订单号补`/v3/posting/fbs/get`、`/v2/posting/fbo/get`，不猜子单号。
- 首次点击立即更新后，该店铺进入每日更新。每天北京时间02:30，重新核对已维护的最早月份至当天，应对延迟入账、跨月补计、退款。自动纳入当前月份。重启后补当天未成功执行的更新，失败至少一小时后重试。
- 凌晨更新时，北京日期可能已经比平台日期早一天，因此请求日期不超出当前UTC日期。完整性及跨月核对按本次已成功拉取的日期快照判断，页面同时显示更新时间与已核对的应计日，不把尚未发生的平台日期当作数据缺失或伪造零收入。
- 同步为后台任务，显示逐日进度、失败原因和数据更新时间。每店仅一个任务，跨进程使用PostgreSQL advisory lock；每日自动最多并行两店，沿用主服务Ozon限流和退避。
- 所有读取、修改、导出、快照和回滚校验当前用户的活动Ozon店铺。插件作用域token不能调用这些接口。只读调用Ozon，不修改商品、价格、订单发货状态。
- 数据库表前缀`app_statistics_`。采购费和月度手工设置独立存储，同步绝不重置；采购费以订单为键，结算月份变化后仍保留。

## 批量维护

- 勾选订单后可逐条编辑或统一填充采购费、贴单费。支持跨页选择，最多5000单。
- 导出当前筛选的全部CSV，UTF-8 BOM。回填采购费用后可导入CSV/XLSX，确认预览后保存。导入时空采购费跳过，防止空模板清除已维护数据。
- 每次修改都在事务中先保存快照；成本及月度设置有递增版本号，并发冲突返回409。回滚仅在没有后续修改时执行，防止覆盖别人的新数据。
- 同步原始流水、订单元数据也记录修改前快照。`app_statistics_changes.kind=sync_day/sync_orders`仅供运维恢复；界面仅展示人工维护及回滚记录。
- 失败邮件复用ERP的告警通道，默认收件人为`313099488@qq.com`，按店铺每小时最多一封；未配置SMTP时仍保留页面失败状态和日志。

## 验证

`npm run test:statistics`执行纯计算回归和可选数据库集成测试。设置`STATISTICS_TEST_DATABASE_URL`后，集成测试仅接受库名含test的数据库，在独立随机schema中验证租户隔离、快照、回滚、并发版本、手工值保护、CSV BOM和后台同步，完成后删除该schema。

测试服务器可运行`node scripts/run-statistics-db-tests.cjs`，它仅在进程内读取测试服务连接配置，不输出密钥。

已有ERP总测试在本次修改前就存在插件发布版本检查失败，不应为了统计模块改动插件包或批量上架逻辑。

## 部署与回滚

1. GitHub拉取并检查测试服关键文件哈希，记录基线。
2. 仅传输本次白名单文件至测试服暂存区；先运行隔离数据库测试。
3. 再次对比测试服基线。变化则停止部署，防止覆盖并行修改。
4. 备份被修改的代码和当时存在的统计数据表。仅覆盖白名单，不同步`.env`、插件、图片、队列或node_modules。
5. 重启`ozon-app-test`，验证身份校验、月筛选、订单费用、采购批改及回滚、月度广告和后台同步。
6. 回滚代码时恢复白名单备份并重启测试服务；统计数据保留，不删除手工采购费。业务数值回滚优先使用修改记录。
